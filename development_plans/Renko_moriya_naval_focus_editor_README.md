## 使用

1. 点击国策，在“编辑”里修改名称、工期、内容概述和大修设想；“现有实现”保留只读源码快照。
2. 拖动节点排版；勾选“联动位置子树”时，位置上依赖它的节点一起移动。画布空白处可拖动平移，滚轮缩放，全览按钮恢复全部节点视野。
3. 前置编辑框每行表示一组必需前置；同一行以逗号分隔的节点为任选其一。不同组必须同时满足。互斥另外填写。
4. 新增节点使用 `Renko_moriya_naval_focus_*`。支持复制、删除、撤销和重做；输入文字时 Ctrl+Z 使用文本框原生撤销，画布焦点下 Ctrl+Z 撤销编辑操作。
5. 自动保存只在当前浏览器生效。完成一轮后下载 JSON，方便交给助手继续修改；也可下载带当前草稿的 HTML，移到其他设备双击使用。
6. “下载审阅文档”导出国策概述和改修设想。编辑和导出均不写入游戏脚本。

同目录 `Renko_moriya_naval_focus_baseline.json` 是首次生成时的基线备份，包含节点、关系、源码片段及来源文件哈希。

## 已记录的实现差异

- `transport_capacity` 是“部队运输船需求”，越低越好。现有提示“运输容量 +10%”不能直接当作实际效果。“强化运输能力”决议实际增加需求 10%；两个国策实际降低需求 10%。
- `experience_gain_navy` 是每日经验固定增量。国策与决议的 0.1 应读为每日 0.10，现有百分比提示不准确。
- `naval_strike` 保留变量增减、原版字段名和 MOD 百分比提示，具体游戏作用没有实机确认。
- “祈风制雷：天候操控”只有 `naval_strike` 变量增加，没有天气事件或天气修正。
- “万祇加持”与“多子嗣之神的庇佑”都可从任意一条互斥路线进入；最终国策要求二者同时完成。
- 入口不立即添加“守矢的舰队强化”；后续国策或取舍决议第一次调用脚本时才添加。取舍变量没有有效上下限；注释中的限制示例不算已实现。
- 共同入口的隐藏舰船奖励是四条造舰生产线，非四艘即时成品；设计创建作用域与 `creator = JAP` 匹配待实机核验。
- 现有国策描述为空，图标均为 `GFX_goal_unknown`；编辑器文字卡片不构成游戏图标制作。
